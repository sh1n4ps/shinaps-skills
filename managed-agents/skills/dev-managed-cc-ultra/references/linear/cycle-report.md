# Cycle完了QAと成果報告

Codexが実行する。Cycle全体を任され、報告まで許可されている場合は、報告用Issue以外の対象Issue（文書・運用のIssueを含む）がすべてDoneであることを確認して続ける。Issue単位の依頼では自動で開始せず、全件完了を案内する。報告だけを明示的に依頼された場合も開始できる。設定が `cycle_report: null` なら報告を行わない。報告を依頼された場合は設定変更を先に行う。設定の不足・不正値は [configuration.md](configuration.md) に従って確認する。

対象のCycle IDとIssue一覧を記録する。日付の到来・自動繰り越し・Cycleの移動・取消を、全件完了の根拠にしない。取消・持ち越し・対象外への変更は、成果と区別して記録する。履歴を取得できない場合は不明と書く。

## 手順

| 順序 | 行動と完了条件 |
| --- | --- |
| 対象を確定 | 既存の報告用Issueと報告書を再利用し、Cycleと対象Issueの受入条件・結果を整理する |
| 全体QA | 設定の `qa_scope` の環境・端末で対象版を確認し、Cycleの変更を合わせた主要導線を検証する。再利用できる検証証拠は活用し、不足する結合・画面操作を補う |
| 素材を記録 | 対象画面・端末のスクショ、動きの説明に必要な短い動画を保存し、対象版・環境と対応づける。秘密値や実利用者の情報を含めない |
| 報告を作成 | 利用者・運営にとって何ができるようになったか、確認結果、制限、次のCycleの実際の計画、必要な人の対応を説明する |
| 保存と確認 | 設定された保存先へ書き込み、本文・画像・リンクの表示を確認する。索引が指定されていればリンクを更新して読み戻す |

全体QAの記録には [qa.md](qa.md) のQAコメントの書式を使い、報告用Issueへ記録する。

## 報告の書き方

- 詳細な検証証拠は報告用Issueへ集め、成果報告には読み手に必要な要約・代表画像・詳細へのリンクを置く。仕様決定・実装済み・公開済みを混同しない。
- 次のCycleの内容は、実際の登録Issue・依存・状態を確認して書く。未登録の予定を確定事項として書かない。
- 報告本文へテスト件数やコミット一覧を転載して作業量を説明せず、成果と確認できたことを伝える。代表素材は証拠と対象版を共有し、既存の素材が古い場合は現在の対象で取り直す。
- 直近の報告と利用者の修正を参考にし、設定の `audience`・`format` と補足ファイルに合わせる。

## 共通Cycle報告テンプレート

```markdown
## <Cycle名> 成果報告
対象期間・Cycleリンク・報告日

## 今回できるようになったこと
利用者・運営への効果を短く説明。

## 主な成果
成果ごとの説明と代表スクショ、必要な短い動画。
仕様決定・実装済み・公開済みを区別。

## 動作確認と残る制限
どの環境・端末で何を確認したか。未確認事項と詳細QAコメントへのリンク。

## 次のCycle
実際の登録Issueに基づく予定・依存・次に実現すること。

## お願いしたいこと
必要な人の対応とIssueリンク。なければ省略。
```

## 未完了と再実行

- 未確認事項やHuman QA待ちがあっても途中報告は保存できるが、全体QAの合格や報告用IssueのDoneにはしない。不具合は修正Issueへ引き継ぎ、修正後に再検証する。
- 再実行では同じCycleの記録を更新し、報告を重複して作成しない。保存・添付・索引の更新の結果が不明なら現状を読み直し、不足する処理だけを行う。
- 報告先がLinearのドキュメントの場合、独立したドキュメントを増やさない運用のチームでも、設定されたCycle報告は例外として作成する。
