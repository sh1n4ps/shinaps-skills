# 担当の起動（Codex）

review・debug・spec・refine・explore のCodexスキルが、名前を挙げる登録済みの担当を Codex のサブエージェントで起動・継続する手順。

- 担当は `spawn_agent` で起動し、毎回 `agent_type`（役割定義名。例 `shinaps-reviewer`）と `fork_turns: "none"` を明示する。`fork_turns` を省略すると親の履歴を引き継ぎ、独立した担当にならない。役割定義には model を書かないので、`model`・`reasoning_effort` はスキルが指定する場合だけ明示し、指定がなければ親セッションから継承する。親セッションの設定は変更しない。
- 同じ役割の複数担当 は、同じ `agent_type` で別々に起動する。担当番号は起動前に固定し、返された ID と対応づけて保持する。
- `task_name` は実行の中で重複しない名前にし、継続では変えない。使う文字は英小文字・数字・`_` だけにする。
- 同じ担当の継続は、同じ ID へ `followup_task` で依頼する。`send_message` は担当のターンを始めないので、継続には使わない。
- 完了は `wait_agent` で待つ。待つ時間は分単位にし、短い間隔で繰り返さない。完了は、担当の完了通知と空でない最終回答で判定する。`wait_agent` の時間切れや `followup_task` の受領だけでは完了としない。
- 同時実行の上限: 枠の数を事前に計算しない。並行起動で枠が足りずに起動できなかった担当は、実行中の担当の完了後にスキルが決めた順で起動する。実行中の担当が無いのに起動できなければ未完了とする。担当の数・独立性・渡す情報は変えない。
- サブエージェントは親の sandbox・承認・tier を引き継ぐ場合がある。読み取り専用の役割は、役割定義の `sandbox_mode = "read-only"` と依頼文の両方で変更を禁止するが、権限の強制境界とは扱わない。
- 質問は利用できる入力手段で一問ずつ行う。進捗は利用できる計画ツールで管理する。他スキルへの引き継ぎは `$shinaps:commit`・`$shinaps:create-pr`・`$shinaps:release` を読む。現在のセッションで提供されていないツールは仮定しない。
- 起動できない、または完了しない担当は未完了として記録する。CLI での起動や他のモデルへ切り替えず、親が代わりに作業して独立確認済みと報告しない。ユーザーのグローバル設定（同時実行の上限を含む）を変更しない。
