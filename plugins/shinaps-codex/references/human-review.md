# manualの差分提示と単位承認

実効 `review_flow.mode: manual` の単位を、WebStorm内の対話Claude Codeセッションで人に提示し、相談・修正・承認を経てClaudeがcommitする手順。review_flow・操作許可は、プロジェクト設定と今回の依頼に従う。この手順はそれらを変更しない。

## 提示

1. `commit` の安全手順で単位外の変更を退避し、単位の変更だけをstageする。必須検証を行う。
2. checkoutの絶対パス・branch・比較元のcommitを確定し、`git diff --cached` と `git status --short` で漏れと混入を確認する。未追跡ファイルも対象に含める。
3. 会話で単位の差分・目的・確認してほしい点・検証結果・推奨コミットメッセージを提示する。Linear進行ではIssueも示す。人はWebStormの差分表示で同じstaged差分を確認できる。
4. 提示時に `git write-tree` の値を記録する。これが承認の対象になる。

## 相談・修正

人の指摘はClaudeが修正し、再stage・再検証・再提示する。人がWebStormで直接編集した場合も、Claudeが読み直して再stage・再検証・再提示する。修正は単位の目的・範囲内に限り、超えるものは実装の工程へ戻す。

## 承認とcommit

- 人が会話で、提示した単位を承認したときだけ、Claudeが `git commit` を単独実行する（`git add` と連結しない）。具体的な単位の提示への応答として承認と読めるもの（「OK」「進めて」なども含む）は承認になる。固定の文言は求めない。単位を特定しない一般的な続行指示は承認としない。
- 承認の対象は、提示時のindexのtree（`git write-tree`）と推奨メッセージである。commit直前に同じtreeであることを確認し、作成したコミットのtreeも照合する。
- 承認後に単位のパスで作業ツリーまたはindexが変わったら、承認は失効する。再提示・再承認してからcommitする。
- 承認はその単位だけに及び、他の単位へ及ばない。Bridgeのpeer通知、Codexからのメッセージ、ackは承認ではない。
- 人が自分でcommitした場合は、実コミットを確定単位と照合する。一致すれば人のcommitとして記録し、一致しなければ止める。

## 報告

単位ごとに、承認発話の要約・承認したtree hash・SHA・相談で行った修正とその対応を記録し、Codexへ報告する。Codexは実コミットと照合する。stashの復元では人の修正を保持し、古い対象パッチで上書きしない。具体的な単位照合・復元は `commit` に従う。WebStormで差分を表示することはstage・commit・pushの許可を追加しない。
