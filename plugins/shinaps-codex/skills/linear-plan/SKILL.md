# 相談を実行可能なIssueへまとめる

相談の目的を確認し、既存の会話・仕様・Issue・コードから分かる内容は再質問しない。仕様が曖昧なら `shinaps:spec`、既存挙動や影響の調査なら `shinaps:explore` を使う。明確な小さな作業は直接整理し、毎回これらのスキルを必須にしない。委託やworktreeの作成は既存の許可に従う。

## 整理と保存

- [設定](../../references/linear/configuration.md)で作業先・Linearの対象・許可を確認する。設定がなくても相談・読み取り・整理案の提示と、利用者が明示的に依頼したIssue更新はできる。別プロジェクトの設定を借用しない。
- [Issueの整理と記録](../../references/linear/issue.md)に従い既存Issueを検索して再利用する。目的・範囲・受入条件・依存・未決事項を整理し、必要ならレビューできる到達点で分割する。要件の正本やspec/exploreの成果物へ参照を付ける。
- spec/exploreから実装へ進む案内があっても、この入口では実装を始めない。調査中の確認や読み取りを、製品コードの変更に広げない。
- Issueの作成・更新は、利用者の明示依頼または設定の `issue_update` が許可する範囲で行う。Claudeは利用者の明示依頼の範囲だけで更新する。チーム設定変更は別の合意が必要。
- 計画対象の調査自体をIssueで管理する規約がある場合も、同じ目的の既存Issueを使い、細かな手順ごとのIssueは増やさない。相談の結果、Issueを作らず保留・見送りにしてもよい。

## 設定の初期作成・変更

依頼の実行に設定が必要で、[設定の読み方](../../references/linear/configuration.md#設定の読み方)で真に未設定と確認した場合だけ、その場で [configuration.md](../../references/linear/configuration.md) の初期設定手順に進む。未決事項を一問ずつ確認し、合意済みの内容を保存する。運用項目を暗黙に補完しない。設定変更は実装開始を意味せず、実行範囲の既定値をYAMLに追加しない。

## 終了と引き渡し

作成・更新したIssue、決定事項、未決事項と依存を示して終了する。相談だけなら結論を返す。開発用ゴールの設定、実装、コミット・公開には進まない。設定のために `linear-execute` から移った場合は、保存・確認後に元の依頼へ戻り、設定と既存の許可の範囲で再開する。それ以外では、利用者が続けて実行を明示的に依頼したときだけ `shinaps:linear-execute` へIssueと成果物を渡し、実行範囲を確定する。
